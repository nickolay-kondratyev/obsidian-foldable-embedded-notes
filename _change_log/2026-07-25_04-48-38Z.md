`ExplicitFold` (`src/livePreview/foldStateField.ts`) inherited `RangeValue`'s default
`MapMode.TrackDel`, which drops a zero-length range only when a deletion spans strictly
ACROSS it. Deleting a folded embed's whole line (with its newline) starts AT the anchor, so
the anchor survived and landed on the line that moved up — the NEXT embed then rendered
folded although the user never folded it. Measured against real Obsidian 1.12.7.

Fix: `override readonly mapMode = MapMode.TrackAfter`. It drops the anchor exactly when a
deletion consumes the character AFTER it, and is inert for insertions AT the anchor, so the
documented "typing at the line start keeps the fold" behaviour is untouched. TrackAfter is
deliberately a touch wider than "the line is gone": deleting only the line's first character
also forgets the fold, and undoing a delete-line brings the embed back unfolded. Both are
accepted — every widened case errs toward SHOWING content.

Covered by a new e2e over its own two-adjacent-embed fixture, verified failing against the
unfixed code first (the reviewer independently reproduced the failure by patching only the
built dev-vault artifact back to TrackDel). Full suite 38/38, lint and build green.

(`sourcePath::L<lineStart>::src::#index`) has the same bug class, narrower because it also
requires a matching `src`.
