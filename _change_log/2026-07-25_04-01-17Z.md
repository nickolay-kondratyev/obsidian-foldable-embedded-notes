Two persistence defects in `src/settings/foldableEmbedsSettingsStore.ts`.

**Unordered writes.** Obsidian does not await a toggle`s `onChange`, so double-clicking the
"start embedded notes collapsed" toggle fired overlapping `setStartCollapsed` calls with nothing
ordering the two `saveData` writes to the same path. `data.json` could keep the value the user
changed their mind about — silently, since both writes succeed and the failure `Notice` never
fires. Saves are now serialized on a promise-queue tail. The tail is deliberately a DIFFERENT
promise from the one returned to the caller: the tail neutralises failures (one failed save must
not poison every save after it, nor surface as an unhandled rejection) while the caller still gets
the rejecting promise, so the settings tab keeps reporting failed saves. Each queued write reads
`this.current` at WRITE time, so the last write always persists what the UI is showing.

**Destroyed keys.** `saveData(this.current)` wrote only the parsed shape, so any other key in
`data.json` was destroyed — e.g. a vault synced from a machine on a newer version with a second
setting, or a hand-added key. The store now retains the keyed part of the persisted object and
saves `{ ...persisted, ...current }`. `asKeyedObject()` drops a non-object root (string / array /
null) rather than spreading it into the saved value. `parseSettings` is untouched and remains the
strict READ path — this was only ever about not destroying data on WRITE.

**Coverage.** New `e2e/settings-persistence.e2e.ts`. The unknown-key test was observed RED against
the pre-fix code. The overlapping-toggle test is a GUARD, not a reproduction — the race could not
be made to fail on demand, so a deterministic ordering test against an out-of-order fake is
deferred to ticket nid_lcehddb2tdcq6qxztmhvhpgga_e, and `asKeyedObject`s array/string/null
branches are folded into nid_fp6hsv6aljxz1ifawlezcfdgu_e. Gate: lint 0 (1 pre-existing warning),
build 0, e2e 37 passed.
