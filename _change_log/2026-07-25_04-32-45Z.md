Ticket nid_ocmytlb996sexgks0wagew41s_e. Four independent e2e problems that each let a real regression go green or made runs flaky.

**1. Vacuous round-trip test (real).** "fold state survives a reading -> editing -> reading round-trip" only switched view mode on the SAME file, so the SAME DOM element stayed in place and the test passed with `src/foldStateStore.ts` completely broken; its "Re-rendered from scratch" comment was false. Both re-render tests now leave the note via `sibling.md` and come back, and a shared `e2e/reRenderGuard.ts` asserts DOM-node identity actually changed — so the test cannot silently regress to the in-place shape again. Proven: with `FoldStateStore.get()` broken the new test goes red while the old one stayed green.

**2. Negated-matcher premise DISPROVEN.** The ticket claimed `not.toHaveClass` passes vacuously on a zero-element locator, citing `matches: options.isNot` in Playwright's `_expectCore`. Measured independently twice: that value is Playwright's *fail-in-either-polarity* sentinel (`if (matches === options.isNot)` is the FAILURE branch), and scalar `not.toHaveClass(/re/)` on a missing element FAILS. Separately, deleting `preventDefault`/`stopPropagation` from `EmbedFoldDom.onTitleClick` detaches nothing on Obsidian 1.12.7 — the suite stays green. So the named regression was not the one described.

What the measurement DID turn up: the ARRAY form `not.toHaveClass([/re/])` *does* pass vacuously. That trap is now documented as a WHY comment in the new shared `e2e/foldAssertions.ts` (which also de-duplicates the fold regex across three specs) so nobody "simplifies" the `toBeAttached()` guard away.

**3. `readPersistedPluginData` (real, narrower than filed).** Playwright does not convert a polled function's rejection into a retry, so a mid-write `data.json` hard-failed the very assertion meant to be patient. A 5x50ms parse-retry already existed but rethrew on the last attempt. It now returns `null` — "no readable answer" — letting `expect.poll` retry. The inner retry was KEPT: `settings-persistence.e2e.ts` reads it once without a poll.

**4. Harness (all real).** `stdio: ["ignore","ignore","pipe"]` so an undrained stdout pipe can no longer fill and freeze Obsidian mid-suite; the boot stderr listener is detached (with `resume()` so the stream stays drained) instead of accumulating the whole session; the launch-failure path awaits `killAndWaitForExit` instead of a bare `kill()`, closing the ENOTEMPTY race against the next spec's sandbox wipe.

Defects 3 and 4 are not sabotage-provable the way 1 is; that is stated plainly rather than dressed up as proof. Suite 37/37 green, lint and build clean. Five follow-ups filed, the notable one being that `preventDefault`/`stopPropagation` is measurably uncovered — flagged, not deleted, since a green suite alone is not evidence that code is dead.
