Review requested via `ask.dnc.md` (find bugs; simplifications welcome). Three parallel reviewers
covered the reading-mode path, the Live Preview/CM6 path, and lifecycle/settings/tooling. Findings
were verified empirically (probe Playwright specs against real Obsidian 1.12.7) rather than by
reasoning alone; several plausible-sounding hypotheses were REFUTED that way and dropped.

Nothing in `src/` was changed — the outcome is 12 tickets.

Two most serious (both fold-state IDENTITY, one per mode):
- Live Preview projects fold state from STALE DOM positions, because `sync()` runs inside
  `update()` and CM runs view plugins BEFORE patching the DOM (`updatePlugins` at
  @codemirror/view index.js:7699, `docView.update` at :7702). Typing ONE character above a
  folded embed loses the fold permanently (measured), or with `startCollapsed` silently
  re-folds an embed the user opened. A `requestMeasure`-based fix was measured to repair all
  reproductions, then reverted.
- Reading mode builds a nested embed's fold key from the CHILD file's ctx, so all occurrences of
  the same parent embed share one key: fold one nested embed, reopen, and an untouched sibling
  is folded too.

Refuted and NOT ticketed (recorded so they are not re-investigated): `sectionHash` racing
async-loaded DOM (fallback unreachable in practice); media embeds leaking observers (measured 0
growth — the real leak is unresolved `file-embed` embeds); the MutationObserver feedback loop;
RangeSet `filterTo` default missing stale anchors; `tr.state` re-entrancy in a StateField update;
tag/manifest divergence in the release path.
