First settings infrastructure in the plugin: `loadData`/`saveData` behind a narrow persistence port, `DEFAULT_SETTINGS` as the single source of truth, and `foldedByDefault(settings, hasFoldMarker)` as the one place the fold-default truth table lives — both render modes project it rather than re-deriving it.

Human-approved scope: the setting only changes the DEFAULT term of the existing `explicitChoice ?? default` decision. No new marker syntax, no CM6 Compartment, no forced rerender of open panes — a change lands on the next render (reopen / mode switch / edit).

Review caught and the implementation fixed two blockers: (1) in Live Preview the first title click was a dead no-op after flipping the setting in an already-open pane, because the click handler read fold state the DOM did not yet show — fixed at the root via `EmbedFoldDom.isFolded`; (2) the 'survives a restart' e2e test could not fail when the write path was broken — now asserts the on-disk data.json and was mutation-proven red.

Gates: lint 0 errors (1 pre-existing ticketed warning), build clean, e2e 34/34 green in real Obsidian.
