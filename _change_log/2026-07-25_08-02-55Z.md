## The bug

An embed BODY renders through the SAME markdown post-processor but with the CHILD
file's `ctx`. MEASURED: `ctx.getSectionInfo()` returns **null** for a nested embed
(the ticket assumed it returned the line inside the child), so key derivation
degraded to the positional fallback `sourcePath::S<hash(sectionText)>::src::#index`
— IDENTICAL for every occurrence of the same parent embed. Folding one nested
embed folded its siblings on the next render, and folding one in `host-a.md`
pre-folded it in `host-b.md`.

## The fix

A nested embed's identity now INHERITS its host's: `<hostKey>::in::<ownKey>`,
resolved through a new per-instance `EmbedFoldKeyRegistry` (`src/embedFoldKeyRegistry.ts`).

**Ordering was the real risk** and was resolved by design rather than by luck: the
registry keys off the host span having been **SEEN** by `process()` (synchronous
registration, lazy memoised derivation), NOT off the host having been **WIRED**,
which would be a MutationObserver race. A probe against real Obsidian 1.12.7
logged zero host-lookup misses in the reading view.

**Cold window:** the two halves of a nested key warm up INDEPENDENTLY — a weak host
half can pair with a strong own half — which the obvious one-line takeover would
have missed. So `superseded` became `supersededKeys: readonly string[]`, and
`nestedIn` emits every weak/strong combination (2^depth - 1; 3 at real depth 2).
Review verified the cartesian set cannot re-merge siblings: siblings share the OWN
half but never the HOST half (warm: occurrence ordinal; cold: lineStart /
indexWithinSection).

## Testing

Two specs in `e2e/foldable-embeds.e2e.ts` (sibling bleed across a re-render;
cross-note bleed) plus `e2e/nested-fold-cold-start.e2e.ts`. All three were
revert-checked RED independently by the reviewer.

Worth remembering: the cold-start spec's first draft was **VACUOUS** — 6/6 green
with the fix reverted, because the vault was already `cacheAtOpen=[WARM]`. The
cold window is now injected deliberately via `ObsidianHarness.withUnindexedNote`.

lint 0, build 0, e2e **52 passed** (was 51), zero skipped.

## Honesty correction

An earlier draft claimed this also fixed Live Preview's cross-note nested bleed.
Review DISPROVED it with an LP probe and the claim was removed from the source and
CLAUDE.md. LP nested embeds share ONE fold state across ALL hosts — pre-existing,
not a regression here — tracked separately.
